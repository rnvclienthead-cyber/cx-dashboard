# Обязательные правила для всех AI-агентов

## Деплой CX Dashboard

1. Перед любым деплоем полностью прочитать `docs/04_ДЕПЛОЙ.md`.
2. Единственный штатный способ деплоя — `scripts/deploy_committed_release.sh`.
3. Релизом всегда является **полный текущий закоммиченный `HEAD`**, а не набор файлов текущего агента и не старый «проверенный базовый коммит».
4. Запрещено исключать более новые коммиты только потому, что их сделал другой агент. Их нужно проверить вместе с релизом. Если какой-либо новый коммит нельзя выпускать — остановиться и сообщить пользователю, а не выкладывать старую версию поверх сервера.
5. Запрещены ручные `rsync --delete frontend/dist`, `scp` backend-файлов и сборка из старого `git archive` в обход штатного скрипта, кроме явно согласованного аварийного восстановления.
6. Скрипт обязан завершиться успешно: чистая сборка из `git archive HEAD`, тесты, серверная блокировка, проверка предка текущего серверного релиза, health-check и запись `.deployed_commit`.
7. Safe-deploy НЕ должен стирать серверные постоянные артефакты, которые раньше автоматически переживали точечный деплой Claude: `/root/cx-dashboard/.env`, `/root/cx-dashboard/bot_api_key.json`, каталоги `/root/cx-dashboard/static/`, `/root/cx-dashboard/uploads/` и их содержимое.
8. После каждого обычного деплоя нужно сохранять доступ nginx к серверным файлам: каталог `/root/cx-dashboard` обязан оставаться проходимым для чтения статики и загрузок.
9. Никогда не собирать frontend на сервере и не восстанавливать локальный `frontend/src` с сервера.
10. Если новая схема safe-deploy конфликтует с этими серверными инвариантами, сначала исправить сам скрипт деплоя, а уже потом выкладывать релиз.
