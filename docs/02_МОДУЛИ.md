# CX Dashboard — Описание модулей

---

## 1. Главный дашборд (Executive Dashboard)

**Путь:** `/`  
**Доступ:** все роли с правом `dashboard`

### Что показывает

| Метрика | Источник данных | Как считается |
|---------|----------------|---------------|
| **Прямые потери (₽)** | wb_claims + wb_cogs | сумма себестоимости одобренных возвратов |
| **PPM (%)** | возвраты ÷ заказы × 100 | одобренные возвраты / всего заказов |
| **CSAT (%)** | wb_feedbacks + ym_feedbacks | отзывы ≥4 звезды / всего отзывов |
| **ИИ обработано** | wb_claims.cat_1 IS NOT NULL | кол-во тегированных записей |
| **Топ-5 проблемных SKU** | сортировка по прямым потерям | ТОП артикулов с наибольшими потерями |
| **Потеря выручки** | wb_logistics.finish_price | сумма цен продажи возвращённых товаров |
| **Потеря прибыли** | выручка − себестоимость | только когда цена > себестоимость |

Все метрики сравниваются с **предыдущим периодом** (те же даты −1 месяц). Показывается дельта в %.

### Фильтры
- Период (начало / конец)
- Маркетплейс: WB / ЯМ / OZON / Все

## 3. ИИ Тегирование (AI Tagging)

**Путь:** `/ai-tagging`  
**Доступ:** `ai_tagging`

### Что делает

Автоматически анализирует комментарии покупателей к возвратам и ставит теги в несколько уровней:

- **Категория 1** — верхнеуровневая причина (например: "Дефект производства")
- **Категория 2** — конкретизация (например: "Трещина корпуса")
- **Категория 3** — деталь (например: "Боковая стенка")

### Откуда берёт данные
- `wb_claims.commentary` — комментарий покупателя к возврату
- `wb_feedbacks.text` — текст отзыва

### Как запустить тегирование
В интерфейсе есть кнопка **"Запустить ИИ"** — она запускает `ai_tagger.py` на необработанных записях.

## 4. Модерация тегов (Moderation)

**Путь:** `/moderation`  
**Доступ:** `moderation`

### Процесс

1. ИИ поставил теги → записи попадают в очередь модерации
2. Менеджер видит возврат: артикул, фото, комментарий покупателя, предложенные теги ИИ
3. Менеджер **подтверждает** или **исправляет** теги
4. Исправления сохраняются в `wb_claims.Корректировка`

### Логика очереди
Показываются возвраты со статусом "Одобрено" (WB вернул деньги покупателю), у которых:
- хотя бы один тег заполнен (поля `1`–`13`)
- поле `Корректировка` пустое (ещё не проверено)

## 8. PPM и Акты

**Путь:** `/ppm`  
**Доступ:** `ppm`

### Что такое PPM

PPM (Parts Per Million) = (кол-во дефектов / кол-во отгрузок) × 100

Это стандартная метрика качества производства. Если PPM > допустимого уровня — отправляется претензионный акт на завод.

### Генерация акта (PDF)

1. Выбрать период и SKU
2. Система показывает расчёт PPM + список возвратов с фото
3. Заполнить: описание дефекта на рус/кит, причина, артикул завода
4. Нажать **"Сформировать акт"** → система генерирует PDF через WeasyPrint
5. PDF скачивается и одновременно сохраняется в Реестр актов

### ABC/XYZ классификация
Товары автоматически делятся на группы:
- **ABC** — по доле выручки (A=топ 80%, B=следующие 15%, C=остальные 5%)
- **XYZ** — по стабильности спроса (X=стабильный, Y=сезонный, Z=нерегулярный)

## 9. Голос покупателя (VoC)

**Путь:** `/voc`  
**Доступ:** `voc`

### Аналитика отзывов

| Раздел | Что показывает |
|--------|---------------|
| Динамика оценок | График средней оценки по времени |
| Тональность | Доля позитивных/негативных/нейтральных |
| Темы отзывов | Авто-категоризация: Доставка, Качество, Размеры, Сборка и т.д. |
| Вопросы покупателей | Классификация вопросов по темам |
| Теги ИИ | Облако тегов + частотный анализ |

### Категории тем (автоматически)
- Доставка — сроки, курьер, опоздание
- Размеры — габариты, не подошёл
- Качество — материал, брак, дефект
- Цвет — оттенок, покрытие
- Комплектация — что входит в набор
- Сборка — инструкция, монтаж
- Возврат/Обмен — замена
- Описание/Фото — соответствие описанию

## 12. Доотправки (Reshipment)

**Путь:** `/reshipment`  
**Доступ:** `reshipment`

### Полный цикл доотправки (подробно — в файле `03_ПРОЦЕССЫ_RACI.md`)

#### Статусы заявки

| Статус | Описание |
|--------|----------|
| `waiting_form` | Клиенту отправлена ссылка, форму ещё не заполнил |
| `pending` | Форма заполнена, ждёт модерации |
| `approved` | Менеджер одобрил |
| `rejected` | Менеджер отклонил |
| `warehouse_confirmed` | Склад подтвердил отправку |
| `warehouse_rejected` | Склад отклонил (нет товара/другая причина) |
| `shipped_yandex` | Отправлено через Яндекс Доставку |
| `shipped_cdek` | Отправлено через СДЭК |

#### Публичная форма (для клиентов)

URL: `https://cxvo.ru/reshipment/form?t=TOKEN` или `https://box.vidovito.com/reshipment/form?t=TOKEN`

Клиент заполняет:
- ФИО получателя
- Телефон
- Адрес доставки (или ПВЗ СДЭК)
- Категория товара
- Описание проблемы
- Фото брака (до 5 фото, макс. 15 МБ каждое)

## 13. Реестр (Registry)

**Путь:** `/registry`  
**Доступ:** `registry`

Реестр всех сформированных претензионных актов PPM. Содержит:
- номер акта
- дата формирования
- артикул и название товара
- завод-производитель
- PPM %
- статус акта (На проверке / Принято / Отклонено)
- история ответов от завода

## 14. Панель управления (Admin)

**Путь:** `/admin`  
**Доступ:** только `admin`

### Возможности

1. **Пользователи** — список всех пользователей, смена роли, сброс пароля
2. **Приглашения** — добавить email в белый список (при регистрации роль назначается автоматически)
3. **Роли** — создать/удалить роль, настроить права (модуль × маркетплейс)

### Как добавить нового пользователя

1. Admin → вкладка "Приглашения" → добавить email + выбрать роль
2. Сообщить пользователю: зайти на `cxvo.ru/login` → нажать "Зарегистрироваться"
3. Ввести тот же email и придумать пароль → автоматически войти в систему
4. Приглашение удаляется (одноразовое)
