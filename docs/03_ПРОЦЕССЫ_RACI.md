# CX Dashboard — Процессы и RACI

## Обозначения RACI

| Буква | Роль | Описание |
|-------|------|----------|
| **R** | Responsible (Исполнитель) | Кто выполняет работу |
| **A** | Accountable (Владелец) | Кто несёт ответственность за результат |
| **C** | Consulted (Консультируется) | Кого спрашивают при необходимости |
| **I** | Informed (Информируется) | Кого уведомляют о результате |

## Участники

| Обозначение | Роль |
|-------------|------|
| **ADM** | Администратор системы |
| **MGR** | Менеджер (оператор) |
| **ANA** | Аналитик |
| **WHS** | Сотрудник склада |
| **AI** | Автоматическая ИИ-система |
| **WRK** | Воркеры (cron-скрипты) |

## Процесс 1: Синхронизация данных с маркетплейсами

**Периодичность:** каждые 2 часа (hourly) и 1 раз в сутки (daily)

```
Шаг                              ADM   MGR   ANA   WHS   AI    WRK
─────────────────────────────────────────────────────────────────────
1. Запуск воркера по cron         I     -     -     -     -     R/A
2. Запрос данных из API маркетпл. -     -     -     -     -     R/A
3. Запись в PostgreSQL            -     -     -     -     -     R/A
4. Логирование в system_logs      -     -     -     -     -     R/A
5. Просмотр статуса в /sync       C     I     I     -     -     -
6. Обработка ошибки воркера       R/A   -     -     -     -     I
```

**Детальные шаги воркера WB (worker.py)**
1. `hourly`: Запрашивает WB API → возвраты за последние 2 ч → сохраняет в `wb_claims`
2. `hourly`: Запрашивает отзывы → сохраняет в `wb_feedbacks`
3. `daily`: Запрашивает заказы → `wb_orders`
4. `daily`: Обновляет ассортимент → `wb_assortment`
5. `daily`: Обновляет финансовую логистику → `wb_logistics`
6. `daily`: Скачивает инвойсы из Google Sheets → `wb_invoices`
7. `daily`: Скачивает себестоимость из Google Sheets → `wb_cogs`

```
4. Сохранение тегов в БД          -     -     -     -     R/A   -
```

```
Шаг                              ADM   MGR   ANA   WHS   AI    WRK
─────────────────────────────────────────────────────────────────────
── ЭТАП 1: ИНИЦИАЦИЯ ─────────────────────────────────────────────────
1. Менеджер пишет "#от" в WB-чате -     R/A   -     -     -     -
2. Система обнаруживает триггер   -     I     -     -     -     R
   (wb_chat.py воркер)
3. Создаётся запись wb_chat_pend. -     -     -     -     -     R
4. Генерируется одноразовый токен -     -     -     -     -     R
5. Ссылка отправляется клиенту    -     I     -     -     -     R
   (WB_CHAT_ENABLED=true)
   или менеджер сам копирует ссыл.-     R     -     -     -     -
   (WB_CHAT_ENABLED=false)

── ЭТАП 2: ЗАПОЛНЕНИЕ ФОРМЫ (КЛИЕНТ) ────────────────────────────────
6. Клиент открывает ссылку        -     I     -     -     -     -
   box.vidovito.com?t=TOKEN
7. Клиент заполняет форму:        -     -     -     -     -     -
   - ФИО получателя
   - Телефон
   - Адрес / ПВЗ СДЭК
   - Категория товара
   - Описание проблемы
   - Фото брака (до 5 шт)
8. Клиент нажимает "Отправить"    -     I     -     -     -     -
9. Заявка создаётся в БД          -     I     -     -     -     R
   статус: new
10. Уведомление в SaleBot         -     I     -     -     -     R

── ЭТАП 3: МОДЕРАЦИЯ ─────────────────────────────────────────────────
11. Менеджер открывает /reshipment -    R     -     -     -     -
12. Изучает заявку:               -     R     -     -     -     -
    - Фото брака
    - Описание клиента
    - Адрес доставки
13. Принимает решение:            -     R/A   -     -     -     -

  ✅ ОДОБРИТЬ:
  14a. Нажать "Одобрить"          -     R/A   -     -     -     -
  15a. Статус → approved          -     I     -     -     -     R
  16a. Уведомление складу         -     I     -     I     -     R

  ❌ ОТКЛОНИТЬ:
  14b. Нажать "Отклонить"         -     R/A   -     -     -     -
  15b. Ввести причину отказа      -     R/A   -     -     -     -
  16b. Статус → rejected          -     I     -     -     -     R

── ЭТАП 4: СКЛАД (упаковка) ──────────────────────────────────────────
17. Склад видит одобренные заявки -     -     -     R     -     -
18. Проверяет наличие товара      -     -     -     R/A   -     -

  ✅ ТОВАР ЕСТЬ:
  19a. Собрать по паклисту, печать этикетки, "Отправлено" - - - R/A - -
  20a. Статус → packed             -    I     -     I     -     R

  ❌ ТОВАРА НЕТ:
  19b. Нажать "Отклонить (склад)" -     -     -     R/A   -     -
  20b. Ввести причину             -     -     -     R/A   -     -
  21b. Статус → rejected           -    I     -     I     -     R

── ЭТАП 5: ОТПРАВКА ──────────────────────────────────────────────────

23. Создать отправление СДЭК/Яндекс, трек-номер - R - R - -

    shipped → in_transit → ready_for_pickup → delivered
```

## Процесс 7: Деплой обновлений (смотри также файл `04_ДЕПЛОЙ.md`)

**Триггер:** разработчик прислал обновление (новая сборка фронта или изменения бэка)

```
Шаг                              ADM   MGR   ANA   WHS   AI    WRK
─────────────────────────────────────────────────────────────────────
1. Получение обновлений           R/A   -     -     -     -     -
2. Сборка фронтенда (ЛОКАЛЬНО)    R/A   -     -     -     -     -
   npm run build
3. Загрузка фронта на сервер      R/A   -     -     -     -     -
   rsync dist/ → /var/www/cx-dashboard/
4. Обновление бэкенда (если нужно)R/A   -     -     -     -     -
   scp файлы → /root/cx-dashboard/
5. Перезапуск бэкенда             R/A   -     -     -     -     -
   systemctl restart cx-backend
6. Проверка работы                R/A   I     -     -     -     -
```

**⚠️ ВАЖНО:**
- `npm run build` — только **локально** на Mac, НИКОГДА на сервере
- Фронт деплоится в `/var/www/cx-dashboard/` (не в `/root/...`)
- После деплоя всегда проверяй https://cxvo.ru
