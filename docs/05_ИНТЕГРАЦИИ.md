## 1. Wildberries API

**Документация:** https://openapi.wildberries.ru  
**Ключ:** переменная `WB_API_KEY` в `.env`

### Что синхронизируется

| Данные | Таблица | Частота |
|--------|---------|---------|
| Возвраты покупателей (рекламации) | `wb_claims` | каждые 2 ч |
| Отзывы покупателей | `wb_feedbacks` | каждые 2 ч |
| Заказы | `wb_orders` | ежедневно |
| Ассортимент (матрица) | `wb_assortment` | ежедневно |
| Финансовая логистика | `wb_logistics` | ежедневно |

### Требуемые права API ключа WB

- ✅ Аналитика (статистика)
- ✅ Возвраты
- ✅ Отзывы
- ✅ Чат продавца (если нужен WB Chat)

### Лимиты API

WB ограничивает запросы. Воркер автоматически соблюдает паузы между запросами.

## 2. WB Чат продавца

**API:** `https://buyer-chat-api.wildberries.ru`  
**Ключ:** тот же `WB_API_KEY` (нужен scope "Чат")

### Как работает

```
Менеджер пишет "#от" → WB API события → wb_chat.py → создаётся токен → ссылка для клиента
```

### Режимы работы

| Переменная | Значение | Поведение |
|------------|---------|-----------|
| `WB_CHAT_ENABLED` | `false` | Мониторинг: триггер фиксируется, бот НЕ пишет в чат |
| `WB_CHAT_ENABLED` | `true` | Активный: бот автоматически отвечает ссылкой на форму |

**Триггер** задаётся в `WB_TRIGGER_KEYWORD` (по умолчанию: `#от`)

### Что происходит при триггере

1. Воркер `wb_chat.py` работает внутри бэкенда постоянно (asyncio task)
2. Опрашивает `/api/v1/seller/events` каждые 30 секунд
3. Видит сообщение с `#от` → извлекает `chatId`, `replySign`, данные клиента
4. Создаёт запись в `wb_chat_pending`
5. Генерирует одноразовый токен → ссылку на форму
6. Если `WB_CHAT_ENABLED=true` → отправляет ссылку через `POST /api/v1/seller/message`

## 3. Яндекс Маркет API

**API:** `https://api.partner.market.yandex.ru`  
**Ключ:** `YM_API_KEY`, `YM_CAMPAIGN_ID`, `YM_BUSINESS_ID` в `.env`

### Что синхронизируется

| Данные | Таблица | Режим |
|--------|---------|-------|
| Заказы | `ym_orders` | hourly |
| Возвраты | `ym_returns` | hourly |
| Отзывы | `ym_feedbacks` | hourly |
| Вопросы покупателей | `ym_questions` | hourly |
| Ассортимент | `ym_assortment` | daily |
| Цены | `ym_prices` | daily |
| Финансовые отчёты | — | reports (3 раза в день) |

### Особенности API

- Пагинация через `paging`, не `pager` (важно!)
- Лимит 420 (rate limit) → воркер пропускает задачу и повторит на следующем запуске
- Финотчёты генерируются асинхронно: сначала `POST` запрос → потом опрос статуса → скачивание

### Возвраты ЯМ

- Синхронизируются только с `2026-01-01` (настраивается в `ym_worker.py`)
- Фото возвратов скачиваются и хранятся локально: `/root/cx-dashboard/static/ym_returns/`
- Маппинг статусов: `REFUNDED` → "Одобрено", `NOT_RETURNED`/`FAILED` → "Отказ"

## 4. OZON API

**API:** `https://api-seller.ozon.ru`  
**Ключи:** `OZON_CLIENT_ID`, `OZON_API_KEY` в `.env`

### Что синхронизируется

| Данные | Таблица | Режим |
|--------|---------|-------|
| Возвраты (FBO) | `ozon_returns` | hourly |
| Заказы (FBS, 30-дн.) | `ozon_orders` | daily |

### Ограничения OZON

- Только **FBO** (продажа со склада OZON), FBS не поддерживается
- Нет фото возвратов — OZON API их не предоставляет
- Нет комментариев клиентов к возвратам
- Пагинация через `last_id` (cursor-based, не page tokens)
- 125k+ записей возвратов в истории

### Ручной backfill (исторические данные)

```bash
ssh root@72.56.240.22
cd /root/cx-dashboard
python3 ozon_worker.py backfill
```

## 5. СДЭК API v2

**API:** `https://api.cdek.ru/v2`  
**Ключи:** `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET` в `.env`

### Для чего используется

Создание отправлений для **доотправок** — когда менеджер одобрил заявку и выбрал СДЭК как способ доставки.

### Настройки по умолчанию

| Параметр | Значение | Описание |
|----------|---------|----------|
| `CDEK_TARIFF_CODE` | 483 | Экспресс ПВЗ→ПВЗ |
| `CDEK_FROM_PVZ_CODE` | (заполнить!) | Код ПВЗ в Казани, откуда сдаёте |
| `CDEK_FROM_CITY` | Казань | Город отправки |
| `CDEK_FROM_CITY_CODE` | 424 | Код города Казань в СДЭК |
| Вес посылки | 300 г | Стандартный пакет |
| Размеры | 15×10×5 см | Стандартный пакет |

**⚠️ Важно:** `CDEK_FROM_PVZ_CODE` должен быть заполнен — без него создание отправлений не работает.

### Авторизация

СДЭК использует OAuth2 `client_credentials`. Токен автоматически обновляется, кэшируется на 1 час.

## 6. Яндекс Object Storage (S3)

**Endpoint:** `https://storage.yandexcloud.net`  
**Ключи:** `S3_ACCESS_KEY`, `S3_SECRET_KEY` в `.env`  
**Бакет:** `cx-dashboard-media`

### Для чего используется

- Хранение **миниатюр фото** возвратов WB (уменьшенные до 1000×1000)
- Снижение нагрузки: вместо прямых ссылок WB используются кэшированные копии

### Логика работы

```
WB фото URL → worker.py → скачать → уменьшить (PIL) → загрузить в S3 → сохранить S3 URL в БД
```

Если S3 не настроен — сохраняется оригинальный URL WB (ссылки могут протухать).

## 7. Google Sheets

**Библиотека:** `gspread`  
**Ключ:** `/root/cx-dashboard/bot_api_key.json` (JSON ключ сервисного аккаунта Google)

### Для чего используется

| Таблица | Переменная | Что синхронизируется |
|---------|-----------|---------------------|
| Инвойсы | `SPREADSHEET_ID_INVOICES` | Соответствие поставка+артикул → номер инвойса |
| Финансы | `SPREADSHEET_ID_FINANCES` | Себестоимость товаров (COGs) |

### Как работает

WB не отдаёт данные о поставках напрямую. Инвойсы вносятся вручную в Google Sheets, откуда воркер автоматически забирает их в БД (`wb_invoices`, `wb_cogs`).
